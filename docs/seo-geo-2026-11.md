# Velero Capital — search (SEO) and AI-answer (GEO) work, November 2026

Scope: velero.capital (this repository). What was wrong, what was changed, and what only the firm can do.
No fact about the firm was added: every title, description, schema field and line of `llms.txt` is taken from copy and data
already on the site.

## 1. What was wrong

1. **Every address served the same empty page.** The site rendered only in the browser. `/secondaries/`, `/services/…` and
   all 50 pages returned one 3 KB shell: the home title, the home description, an empty `<div>`, and a canonical link
   pointing at the home page. Google can run JavaScript, but most AI crawlers (GPTBot, ClaudeBot, PerplexityBot) and link
   previews (LinkedIn, WhatsApp, Slack) do not, so to them the site had no content and one page.
2. **Unknown addresses returned 200.** A catch-all rewrite served the shell for any URL, so there was no real 404.
3. **Two hosts.** `www.velero.capital` and `velero.capital` both answered with 200, and the "Summarise with" links used www.
4. **Duplicate descriptions.** Home, Company and Investment Strategies shared one description; several were over 160
   characters. Page titles were the bare page name ("Solutions | Velero Capital").
5. **Hidden answers and figures.** FAQ answers were only in the page while their row was open; the firm figures started at
   0 and counted up, so a reader of the HTML saw "$0M+".
6. **Old WordPress addresses redirected only in the browser**, after the app loaded, so their link value did not pass on.
7. **Thin structured data.** One Organization block on every page; no page, breadcrumb, service or FAQ data.

## 2. What was changed

**Prerendering.** `npm run build` now renders all 50 pages to static HTML (`scripts/prerender.mjs`,
`src/entry-server.tsx`) and the browser hydrates that markup. Each file carries its own content, `<title>`, description,
canonical URL, Open Graph and Twitter tags.

**Head and structured data** (`src/lib/useTitle.ts`, set per page):
- Descriptive titles, e.g. "Secondaries: Direct Secondaries & LP Fund Stakes | Velero Capital"; unique descriptions,
  clipped on a whole word at 160 characters.
- Site-wide `Organization` (both offices, contact point, areas of expertise, LinkedIn) and `WebSite`, in `index.html`.
- Per page: `WebPage` / `AboutPage` / `ContactPage` / `CollectionPage` and `BreadcrumbList`; `Service` on the four
  strategy pages, ten service pages and 24 sector pages; `FAQPage` wherever questions are shown (Company, Solutions and
  each sector page); an `ItemList` of services.
- The organisation is typed `Organization`, not `FinancialService`: the legal page makes no statement about licences or
  registrations, and the schema should not imply one.

**Content readable without scripts.** All FAQ answers stay in the HTML (closed rows are hidden, not removed). The firm
figures render as their real values and count up from zero only when scrolled into view. The four firm FAQs that were in
`src/data/site.ts` but shown nowhere are now a "Questions, answered" section on the Company page.

**For AI assistants.**
- `/llms.txt`: a short markdown map of the firm (what it is and is not, who it works with, offices, contact, figures with
  their as-of date, every strategy, service and sector with a one-line description, FAQs).
- `/llms-full.txt`: the full text of every page as markdown, generated from the rendered pages on each build.
- `robots.txt` names the AI search and assistant crawlers and allows them.

**Technical.**
- Real 404: unknown addresses get `404.html` with a 404 status and `noindex`.
- `www` redirects to the bare domain; every URL ends in a slash (one form per page).
- Thirteen old WordPress addresses (`/about-us`, `/otc-investment`, `/team` …) are now permanent server redirects.
- `sitemap.xml` is generated from the route table on each build.
- Hashed assets are cached for a year. The walkthrough film (client-only, no text) is marked `noindex`.
- The build fails on a duplicate title or description, a page without exactly one `<h1>`, or an image without alt text.

## 3. What only the firm can do

These have more effect on AI answers than anything in the code, because assistants weigh what other sites say.

1. **Google Search Console and Bing Webmaster Tools.** Verify velero.capital in both and submit
   `https://velero.capital/sitemap.xml`. Bing matters for GEO: ChatGPT search and Copilot draw on its index.
2. **Consistent entity facts everywhere.** The same one-line description, Dubai address and website on the LinkedIn
   company page, Crunchbase, PitchBook and any directory listing. Add those profile URLs to `sameAs` in `index.html`.
3. **A named person.** The team page is hidden by choice. Assistants trust firms more when a founder is identifiable; if
   that changes, add the founder to the Organization data and the Company page.
4. **Corporate identification.** The legal page says entity details are available on request. A named legal entity and
   registration (once confirmed by counsel) is the single strongest trust signal still missing.
5. **Third-party mentions.** Press, conference listings, co-adviser announcements and partner pages that link to
   velero.capital. Assistants cite sources; a firm described only by its own site is rarely cited.
6. **Original, dated writing.** There is no insights section because there is nothing verified to publish. Two or three
   substantive pieces a year (how a secondary closes, Gulf–US market entry) give assistants something to quote.
7. **Keep the figures dated.** `STATS_ASOF` in `src/data/site.ts` is published in `llms.txt`; update it with the numbers.
8. **Sector pages.** The 24 Solutions pages still describe activity that the October audit flagged as unconfirmed. They
   are now fully indexable, so confirm or trim them.

## 4. Checking it

- `npm run build && npm run preview`, then view source on any page: the content, title and JSON-LD are in the HTML.
- After deploy: `curl -I https://velero.capital/no-such-page/` should say 404; `curl -I https://www.velero.capital/`
  and `curl -I https://velero.capital/about-us` should say 308.
- Google Rich Results Test and the Schema.org validator on a service page and a sector page.
